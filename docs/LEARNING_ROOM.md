# Backend Foundations Learning Room

This is your learning base for understanding the project while still selling it.

You do not need to know everything before selling. You need to know enough to:

1. Explain what the product does.
2. Answer basic client questions honestly.
3. Understand the changes being made.
4. Slowly become independent with backend, frontend, security, and deployment.

## The Simple Product Explanation

This project is becoming a lightweight dashboard for bookkeepers and accountants.

It helps them see:

- who owes money
- which invoices are overdue
- which receipts or documents are missing
- which clients need attention today
- simple reports they can export
- bank CSV transactions that need matching

The first sellable version is not a full accounting system. It is a focused client-control dashboard.

## The Tech Stack

Frontend:

- HTML, CSS, and JavaScript
- Runs in the browser
- Shows the dashboard, forms, tables, reports, and buttons

Backend:

- Python
- FastAPI
- Receives requests from the frontend
- Handles logins, businesses, clients, invoices, expenses, reports, uploads, and bank imports

Database:

- SQLite for local development
- Postgres later for deployment
- Stores users, businesses, clients, invoices, expenses, audit logs, and bank transactions

Exports:

- ReportLab creates PDF invoices and PDF reports
- CSV exports are generated by the backend

Security:

- Passwords are hashed
- Login returns a bearer token
- Each user can only access businesses they belong to
- Real production still needs stronger hosting, backups, HTTPS, secrets handling, and monitoring

## Learning Path

### Stage 1: Know The Product

Goal: explain the app in 60 seconds.

Learn:

- what a dashboard is
- what a client workflow is
- what invoices, expenses, receipts, and reports are
- what the R2,800 pilot includes

Practice:

- explain the product out loud
- open `frontend/bookkeeper.html`
- open the proof PDF in `evidence/bookkeeper-client-dashboard-proof.pdf`

### Stage 2: Frontend Basics

Goal: understand what the user sees.

Learn:

- HTML is structure
- CSS is style
- JavaScript is behavior
- forms collect data
- tables show records
- buttons trigger actions

Practice:

- change one heading in `frontend/bookkeeper.html`
- change one color
- trace one button link

### Stage 2.5: CLI Basics

Goal: understand typed commands.

Learn:

- a CLI is a command line interface
- commands can run tests, start servers, generate reports, and automate work
- backend tools often start as CLIs because they are fast and scriptable

Practice:

- read `docs/CLI_EXPLAINED_SIMPLE.md`
- run `python tools/generate_bookkeeper_evidence.py`
- explain what the command produced

### Stage 3: Backend Basics

Goal: understand what happens when the app saves or loads data.

Learn:

- API means the frontend asks the backend for something
- endpoint means a URL that performs an action
- CRUD means create, read, update, delete
- JSON is the data format passed between frontend and backend

Practice:

- open `http://127.0.0.1:8000/docs`
- find `/accounting/auth/register`
- find `/accounting/businesses/{business_id}/invoices`
- explain what `POST`, `GET`, `PATCH`, and `DELETE` mean

### Stage 4: Database Basics

Goal: know where records live.

Learn:

- tables store records
- users, businesses, clients, invoices, and expenses are tables
- SQLite is a local database file
- Postgres is the deployment database

Practice:

- find the model classes in `calculator/accounting_db.py`
- explain one table, such as `Invoice`

### Stage 5: Security Basics

Goal: answer basic client trust questions.

Learn:

- passwords must never be stored as plain text
- tokens prove a user is logged in
- permissions stop users seeing other businesses
- sanitized demo data is safer than real client data
- production needs HTTPS, backups, secret management, and logging

Practice:

- explain why clients should send sanitized data for pilots
- find `hash_password` in `calculator/accounting_db.py`
- find `require_current_user` in `calculator/accounting_api.py`

### Stage 6: Deployment Basics

Goal: understand how the app goes online.

Learn:

- local means running on your machine
- deployment means running on a server
- Render can host the FastAPI backend
- environment variables store settings
- Postgres stores production data

Practice:

- read `render.yaml`
- find `ACCOUNTING_DATABASE_URL` in the README
- explain why local SQLite is not enough for serious production

## Daily Learning Rhythm

Use this rhythm:

1. Spend 20 minutes selling or outreach.
2. Spend 20 minutes learning one technical idea.
3. Spend 10 minutes explaining what you learned in your own words.

Never spend the whole day learning and zero time selling. The money comes from shipping and conversations.

## Questions To Ask Me

Use these prompts:

- "Explain this file like I am new: calculator/accounting_api.py"
- "Teach me one backend concept from this project"
- "Quiz me on frontend basics"
- "Show me how login works in this app"
- "Explain cybersecurity risks in this project"
- "Give me a client-safe explanation of the database"
- "What should I learn today?"

## Rule

Every time we build a feature, you should ask:

"What does this mean in simple words, and how do I explain it to a client?"

That is how you stop depending blindly and start becoming dangerous in a good way.
